# Gemini AI Telegram Bot

Telegram-бот на Python + aiogram 3. В боте только Google Gemini:
- 3 независимых API-ключа;
- одна и та же модель для всех ключей;
- выбор API-кнопками;
- отдельная история для каждого пользователя и каждого выбранного ключа;
- история находится только в оперативной памяти и очищается после перезапуска;
- обработка ошибок ключа, квоты и временных ограничений.

## 1. Создай Telegram-бота
В Telegram открой BotFather, создай бота командой `/newbot` и скопируй токен.

## 2. Получи ключи Gemini
Создай до трёх API-ключей в Google AI Studio. Каждый ключ должен иметь доступ к выбранной модели.
Не публикуй ключи в GitHub и не отправляй их в чаты.

## 3. Загрузка на GitHub
Распакуй архив и загрузи содержимое папки в новый GitHub-репозиторий.
Файл `.env` не добавляй. В репозитории есть только `.env.example` с названиями переменных.

## 4. Render
Создай Background Worker и подключи GitHub-репозиторий:
- Runtime: Python
- Build Command: `pip install -r requirements.txt`
- Start Command: `python bot.py`

В Environment добавь:
- `BOT_TOKEN` — токен BotFather
- `GEMINI_API_KEY_1` — первый ключ
- `GEMINI_API_KEY_2` — второй ключ
- `GEMINI_API_KEY_3` — третий ключ
- `GEMINI_MODEL` — `gemini-3.8-flash`

Если ключей пока меньше трёх, не заполняй отсутствующие переменные: соответствующие кнопки будут показываться как ненастроенные.

`render.yaml` уже содержит конфигурацию Background Worker. При использовании Blueprint проверь выбранный тариф: Background Worker на Render может быть платным.

## 5. Запуск локально (необязательно)
Установи зависимости:
`pip install -r requirements.txt`

Задай переменные окружения и запусти:
`python bot.py`

## Важно про API и лимиты
Три ключа не объединяют квоты в одну общую квоту и не гарантируют больше бесплатных запросов. Ключи могут относиться к одному проекту Google и иметь общие ограничения. Если Google вернёт ошибку квоты, бот покажет сообщение «Лимит исчерпан». Ошибки 429 без явного признака исчерпания квоты будут показаны как временное ограничение.

## История
История хранится в RAM процесса. После перезапуска Render она исчезнет. В этом варианте история не записывается в базу данных или на диск.


## Важно: тип сервиса на Render

Это Telegram-бот на long polling, поэтому в Render он должен быть создан как **Background Worker**, а не Web Service.
Сообщение `No open ports detected` для Background Worker не является ошибкой. Если оно появляется вместе с ошибкой о необходимости порта и сервис помечен как Web Service, создай Background Worker из этого же репозитория с командой запуска `python bot.py`.

## Исправления последней версии

- Игнорируется безвредная ошибка Telegram `message is not modified` при повторном обновлении одинакового меню.
- Для Gemini 503/429/5xx выполняется переход к следующему настроенному ключу.
- Сокращено ожидание одного запроса, чтобы бот не оставлял пользователя надолго без ответа.


## Режим Render Web Service

Эта версия запускает одновременно Telegram long polling и HTTP health server:
- Render направляет HTTP-проверки на `/health` (также отвечает `/`).
- Сервер слушает `0.0.0.0:$PORT`, как требует Render Web Service.
- Start Command: `python bot.py`.
- Build Command: `pip install -r requirements.txt`.

На бесплатном Render Web Service приложение может засыпать после периода отсутствия входящих HTTP-запросов. Telegram long polling сам по себе не гарантирует, что Render будет считать сервис активным. Поэтому бесплатный Web Service не гарантирует круглосуточную доступность бота.


## Telegram Webhook для Render Web Service

В этой версии используется **Webhook вместо getUpdates/Long Polling**. Это правильный режим для Web Service и устраняет конфликт `TelegramConflictError: terminated by other getUpdates request`, если старые экземпляры polling остановлены.

Render автоматически предоставляет `RENDER_EXTERNAL_URL` и `PORT`. В Environment добавь `WEBHOOK_SECRET` — случайную строку из латинских букв и цифр длиной 32–64 символа. После Deploy в логах должно появиться `Telegram webhook configured`.

Важно: останови старый Worker, локально запущенный бот и все другие сервисы, использующие тот же BOT_TOKEN. Не запускай одновременно старую polling-версию и webhook-версию. У Telegram один бот не может одновременно использовать webhook и getUpdates.
